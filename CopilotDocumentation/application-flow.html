🔄 NESI Application Flow Diagrams

Data Flow Overview

This document visualizes the data flow through the NESI application for key business processes. Each diagram shows the sequence of steps, actors involved, system components, and data transformations as information moves through the application layers.

📝 Quote to Work Order Flow

Overview

This flow shows how a customer quote progresses through the system from creation to work order conversion, tracking approvals, customer acceptance, and final handoff to operations.

Customer Request

Customer → Sales Rep

Input: Project requirements, specifications, timeline

Output: Opportunity created in CRM

↓

Quote Creation

Sales Representative → Quote Module

  • UI: Angular Quote Component
  • API: POST /api/page/quotes
  • BLL: QuoteService.CreateQuote()
  • DAL: Entity Framework saves Quote entity
  • DB: INSERT into Quote, QuoteLine tables

Data Created: Quote header, line items, pricing, terms

Status: Draft

↓

Quote Calculation

System Automatic

  • Sum line item totals (qty × unit price)
  • Calculate subtotal
  • Apply tax rate based on customer location
  • Calculate grand total
  • Calculate profit margin

Business Logic: QuoteCalculation.cs

↓
💡 Decision: Requires Approval?

Condition: Total Amount > $50,000 OR Discount > 15%

  • YES → Proceed to Step 4
  • NO → Skip to Step 6
↓

Internal Approval Request

Sales Rep → Approval Workflow

  • Sales Rep clicks "Submit for Approval"
  • System routes to Manager based on business rules
  • Manager notified via SignalR + Email
  • Notification appears on Manager dashboard

Status: Pending Approval

↓

Manager Review & Approval

Manager → Approval Module

  • Manager reviews quote details
  • Checks profit margins and customer history
  • Approves or rejects with comments
  • API: PUT /api/page/quotes/{id}/approve

Status: Approved (or Rejected)

↓

Quote Generation & Delivery

Sales Rep → Document Generation

  • Generate PDF quote document
  • Email to customer contacts
  • Upload to customer portal (if enabled)
  • Log customer access/downloads

Status: Sent to Customer

Data Flow: Quote data → PDF template → Email service → Customer

↓

Customer Review

Customer → Customer Portal / Email

  • Customer receives and reviews quote
  • May request revisions (loop back to Step 2)
  • Accepts quote via email or portal

Status: Customer Approved

↓

Convert to Work Order

Sales Rep → Work Order Module

  • Sales Rep clicks "Convert to Work Order"
  • API: POST /api/page/quotes/{id}/convert
  • BLL: QuoteService.ConvertToWorkOrder()
  • System creates work order from quote template
  • Copies customer, line items, dates, assignments
  • Links quote reference to work order
  • DB: INSERT into WorkOrder, WorkOrderLine tables

Quote Status: Converted

Work Order Status: Open

↓

Work Order Assignment

Project Manager → Work Order Module

  • PM assigns team members to work order
  • Sets schedule and milestones
  • Assigns tasks to technicians
  • SignalR notifies assigned users
  • Work order appears on technician dashboards

Status: Assigned / In Progress

↓

Work Execution

Field Technicians → Multiple Modules

  • Log time via Timesheet module
  • Update work order status and notes
  • Upload photos and documents
  • Request materials (triggers PO flow)

Data Captured: Labor hours, materials used, completion %

⏱️ Time Entry to Payroll Flow

Time Entry

Employee → Timesheet Module

  • UI: Timesheet component
  • Employee selects work order or project
  • Enters date, hours, pay type, job type
  • Adds notes about work performed
  • API: POST /api/page/timesheet
  • BLL: TimesheetService.SaveEntry()
  • Validation: Hours > 0, <= 24, required fields

Data Storage: Timesheet table

↓

Business Logic Processing

System Automatic

  • Calculate overtime (if > 40 hours/week)
  • Allocate to business unit
  • Link to work order for job costing
  • Calculate cost (hours × employee rate)
  • Update work order hours summary
↓

Timesheet Submission

Employee → Approval Workflow

  • Employee reviews weekly timesheet
  • Clicks "Submit for Approval"
  • System validates completeness
  • Routes to supervisor
  • Supervisor notified

Status: Pending Approval

↓

Supervisor Review

Supervisor → Approval Module

  • Reviews employee timesheets
  • Verifies hours against work orders
  • Checks for anomalies (excessive hours, wrong codes)
  • Approves or rejects with comments

Status: Approved (or Rejected)

↓

Payroll Export

System Batch Process → Payroll System

  • Scheduled batch job runs (weekly/bi-weekly)
  • Queries approved timesheets for pay period
  • Aggregates hours by employee and pay type
  • Calculates totals (regular, overtime, PTO)
  • Generates export file (CSV/XML)
  • Transfers to payroll system (FTP/API)

Data Format: Employee ID, Pay Type, Hours, Rate, Total

↓

Job Costing Update

System Automatic

  • Approved hours allocated to work orders
  • Labor costs calculated and summed
  • Work order budget tracking updated
  • Available in job cost reports
🛒 Purchase Order Flow

Material Need Identification

Project Manager / Technician

  • Work order requires materials
  • Check inventory availability
  • If not available, create purchase request
↓

Vendor Selection

Purchasing Agent → Vendor Module

  • Search vendors by specialty
  • Review vendor ratings and history
  • Compare pricing and lead times
  • Select preferred vendor
↓

PO Creation

Purchasing Agent → PO Module

  • API: POST /api/page/purchaseorder
  • Enter PO header (vendor, ship to, terms)
  • Link to work order
  • Add line items (part #, qty, price)
  • Allocate to business unit
  • System calculates totals with tax

Status: Draft

↓
💡 Decision: Requires Approval?

Condition: Total Amount > Approval Threshold

  • YES → Proceed to Step 4
  • NO → Skip to Step 5
↓

Manager Approval

Manager → Approval Module

  • Review PO details and budget impact
  • Verify business necessity
  • Approve or reject

Status: Approved

↓

PO Transmission

System → Vendor

  • Generate PO PDF document
  • Email to vendor contacts
  • Vendor portal notification (if enabled)
  • Log transmission

Status: Sent to Vendor

↓

Vendor Processing

Vendor

  • Receives PO
  • Acknowledges receipt
  • Provides estimated ship date
  • Prepares order
  • Ships materials
↓

Receiving

Warehouse Staff → Receiving Module

  • Materials arrive at dock
  • Scan or search for PO
  • API: POST /api/page/purchaseorder/{id}/receive
  • Enter received quantities per line
  • Note any discrepancies
  • System updates inventory quantities
  • Materials available for work orders

Status: Received (Full or Partial)

↓

Invoice Matching (3-Way Match)

Accounting → AP Module

  • Vendor invoice received
  • Match invoice to PO
  • Match to receiving records
  • Validate quantities and prices
  • Resolve discrepancies
  • Approve for payment
↓

Payment Processing

Accounting System → Vendor

  • Payment scheduled based on terms
  • Check or ACH generated
  • Payment sent to vendor
  • PO marked as paid

Status: Closed

↓

Cost Allocation

System Automatic

  • PO costs allocated to work order
  • Material costs added to job costing
  • Budget tracking updated
  • Available in financial reports
🔐 Authentication Flow

User Login Request

User → Angular Login Component

  • User enters username and password
  • Clicks "Sign In" button
  • Angular form validation
↓

Token Request

Angular → OAuth Endpoint

  • Endpoint: POST /token
  • Headers: Content-Type: application/x-www-form-urlencoded
  • Body: grant_type=password&username=...&password=...
↓

OWIN Authentication Pipeline

OWIN Middleware

  • Request intercepted by OAuth middleware
  • NesiAuthorizationServerProvider.GrantResourceOwnerCredentials()
↓

Credential Validation

AuthRepository → Database

  • Query User table by username
  • Verify user is active
  • Hash submitted password
  • Compare to stored password hash
  • Log login attempt (success/failure)
  • Record IP address and timestamp
↓
💡 Decision: Valid Credentials?
  • YES → Proceed to Step 5
  • NO → Return 401 Unauthorized, error message
↓

User Data Loading

AuthRepository

  • Load user permissions (pages, privileges)
  • Load business unit assignments
  • Load role information
  • Create User object with full profile
↓

Token Generation

OAuth Server

  • Generate unique GUID for user session
  • Store user in Global.OnlineUser cache
  • Create ClaimsIdentity with user data
  • Generate access token (JWT-like)
  • Generate refresh token
  • Set expiration times
↓

Token Response

OAuth Server → Angular

  • Response (200 OK):
  • access_token: "Bearer token string"
  • token_type: "bearer"
  • expires_in: seconds
  • refresh_token: "refresh token string"
  • userName: "username"
↓

Client Token Storage

Angular AuthService

  • Store access_token in LocalStorage
  • Store refresh_token in LocalStorage
  • Store user profile data in @ngrx store
  • Set authentication state to true
  • Navigate to dashboard
↓

Subsequent API Requests

Angular → Web API

  • HTTP Interceptor adds Bearer token to headers
  • Header: Authorization: Bearer {token}
  • OWIN middleware validates token
  • Extracts user identity from token
  • Sets HttpContext.User
  • Controller accesses CurrentUser
↓

Session Maintenance

System

  • Token expires after configured time
  • Client uses refresh token to get new access token
  • Automatic token refresh before expiration
  • User remains logged in seamlessly

🔑 Key Takeaways

  • Multi-Layer Architecture: All flows traverse Frontend → API → BLL → DAL → Database
  • Approval Workflows: Business logic determines routing based on dollar amounts and business rules
  • Real-time Notifications: SignalR pushes updates to relevant users at key stages
  • Data Linkage: Entities are connected (Quote → Work Order, PO → Work Order, Time → Work Order)
  • Audit Trail: Every step logged for compliance and troubleshooting
  • Security: OAuth tokens validated on every API request, authorization filters check permissions
