👤 NESI User Journey & Workflows

User Journey Overview

This document maps out typical user journeys through the NESI application, illustrating how different user personas interact with the system to accomplish their daily tasks. Each journey represents a real-world workflow from start to completion.

👥 User Personas

🏢 Sarah - Field Technician

Role: Field Engineer

Primary Tasks: Time tracking, work order updates, expense entry

Goals: Log hours accurately, update work status, submit expenses quickly

Pain Points: Mobile access, complex timesheet entry, unclear work order details

💼 Mike - Sales Representative

Role: Sales Team Member

Primary Tasks: Customer management, quote creation, opportunity tracking

Goals: Close deals, generate accurate quotes, maintain customer relationships

Pain Points: Quote complexity, approval delays, customer data accuracy

📊 Jennifer - Project Manager

Role: Project Management

Primary Tasks: Work order management, resource allocation, project tracking

Goals: Complete projects on time and budget, optimize resource utilization

Pain Points: Resource conflicts, status visibility, budget overruns

🛒 David - Purchasing Agent

Role: Procurement Team

Primary Tasks: Purchase order creation, vendor management, receiving

Goals: Procure materials efficiently, manage vendor relationships, control costs

Pain Points: Vendor response times, budget tracking, receiving discrepancies

🎯 Journey 1: Employee Login to Timesheet Entry

Persona: Sarah (Field Technician)

Scenario: End of day, Sarah needs to log her hours for multiple work orders

🔐 Authentication

Action: Sarah opens NESI in her browser and navigates to the login page

  • Enters username and password
  • Clicks "Sign In" button
  • System validates credentials via OAuth
  • Bearer token generated and stored

UI Elements: Login form, company logo, "Forgot Password" link

Duration: 10-15 seconds

↓

🏠 Dashboard / Home Page

Action: Sarah lands on her personalized dashboard

  • Views assigned tasks and work orders
  • Sees pending timesheet entries
  • Checks notifications (SignalR real-time updates)
  • Reviews upcoming vacation requests

UI Elements: Dashboard widgets, navigation menu, notification bell, search bar

Duration: 30-60 seconds (review)

↓

⏱️ Navigate to Timesheet

Action: Sarah clicks on "Timesheet" from the main navigation

  • System checks PageAuthorization for Timesheet page
  • Loads timesheet module (Angular component)
  • Fetches current week's timesheet data via API
  • Displays calendar view with existing entries

API Call: GET /api/page/timesheet

Duration: 2-3 seconds

↓

📝 Select Work Order

Action: Sarah chooses the work order she worked on today

  • Clicks "Add Time Entry" button
  • Opens work order picker dialog
  • Searches for work order by number or customer
  • System filters by business unit authorization
  • Selects work order from dropdown list

UI Elements: Dropdown, search filter, work order details preview

Duration: 10-20 seconds

↓

🕐 Enter Time Details

Action: Sarah fills in time entry details

  • Selects date (defaults to today)
  • Chooses pay type (Regular, Overtime, Double Time)
  • Enters hours worked (8.0)
  • Selects job type (Field Work, Installation, Troubleshooting)
  • Adds optional notes/comments
  • Allocates hours to business unit if multi-unit

Validation: Hours must be > 0, must not exceed 24, pay type required

Duration: 30-45 seconds

↓

💾 Save Time Entry

Action: Sarah clicks "Save" to submit time entry

  • Client-side validation checks all required fields
  • Angular dispatches saveTimeEntry action
  • @ngrx effect calls TimeSheetService.saveEntry()
  • POST request to /api/page/timesheet with Bearer token
  • API validates authorization and business rules
  • BLL calculates totals and applies pay rules
  • Entity Framework saves to database
  • Success response returns to client

API Call: POST /api/page/timesheet

Duration: 1-2 seconds

↓

✅ Confirmation & Next Action

Action: System confirms save and updates UI

  • Success toast notification displayed
  • Timesheet grid refreshes with new entry
  • Daily/weekly totals recalculated
  • Sarah can add more entries or submit timesheet for approval

Next Steps: Add more time entries, add expenses, or submit for approval

💰 Journey 2: Sales Quote Creation to Work Order Conversion

Persona: Mike (Sales Representative)

Scenario: Mike creates a quote for a new customer project and converts to work order

Quote-to-Work Order Workflow

🔍 Customer Search/Creation

  • Navigate to Customers module
  • Search for existing customer or create new
  • Enter/verify customer details (name, address, contacts)
  • Assign customer to business unit

Duration: 2-5 minutes (new customer), 30 seconds (existing)

↓

📋 Create New Quote

  • Click "Create Quote" from customer page
  • Select quote type (Time & Material, Fixed Price)
  • Enter project description and scope
  • Set estimated start and completion dates
  • Assign project manager/responsible employee

API Call: POST /api/page/quotes/new

Duration: 2-3 minutes

↓

📝 Add Quote Line Items

  • Add labor line items (job types, hours, rates)
  • Add material line items (inventory or custom)
  • Add equipment/asset charges
  • Apply markups and discounts
  • System calculates totals automatically

Features: Template-based entry, copy from previous quote, bulk import

Duration: 10-20 minutes

↓

📊 Review and Adjust Pricing

  • Review total quote amount
  • Check profit margins
  • Compare to customer rate history
  • Adjust pricing if needed
  • Add terms and conditions

Reports: Quote summary, profit analysis, rate comparison

Duration: 5-10 minutes

↓

✅ Submit for Approval (if required)

  • Click "Submit for Approval" button
  • System checks approval thresholds (dollar amount)
  • Quote routed to manager for approval
  • Manager receives notification (SignalR + Email)
  • Manager reviews and approves/rejects

Status: Pending Approval → Approved or Rejected

Duration: Minutes to hours (depends on manager availability)

↓

📧 Send Quote to Customer

  • Generate PDF quote document
  • Email quote to customer contacts
  • Customer views quote in portal (optional)
  • Track customer quote views and downloads

Status: Sent to Customer

Duration: 2-3 minutes

↓

✔️ Customer Approval

  • Customer reviews quote
  • May request revisions (iterate steps 3-6)
  • Customer approves via email or portal
  • Mike updates quote status to "Customer Approved"

Status: Customer Approved

Duration: Days to weeks (customer-dependent)

↓

🔧 Convert to Work Order

  • Mike clicks "Convert to Work Order" button
  • System validates quote status (must be approved)
  • Creates work order from quote template
  • Copies line items, customer, dates, assignments
  • Sets work order status to "Open"
  • Links quote to work order (reference)

API Call: POST /api/page/quotes/{id}/convert

Status: Quote Converted → Work Order Created

Duration: 5-10 seconds

↓

🎯 Work Order Assignment

  • Project manager assigns team members
  • Schedules start date and milestones
  • Assigns tasks to technicians
  • Technicians receive notifications (SignalR)
  • Work order appears on technician dashboards

Handoff: From Sales to Operations

🛒 Journey 3: Purchase Order Workflow

Persona: David (Purchasing Agent)

Scenario: Create PO for materials needed for work order, receive goods, and process

📦 Identify Material Need

Trigger: Work order requires materials not in inventory

  • Project manager flags material requirement
  • David reviews work order materials list
  • Checks inventory availability
  • Determines need for purchase
↓

🏭 Select Vendor

  • Navigate to Vendors module
  • Search vendors by specialty/capability
  • Review vendor history and ratings
  • Compare pricing (if multiple vendors)
  • Select preferred vendor

Considerations: Price, delivery time, vendor reliability, terms

↓

📝 Create Purchase Order

  • Click "Create PO" button
  • Select vendor from dropdown
  • Link to work order (for cost tracking)
  • Enter PO header details (ship to, terms, required date)
  • Add line items (part number, description, quantity, unit price)
  • Allocate costs to business unit
  • System calculates totals with tax

API Call: POST /api/page/purchaseorder

↓

✅ PO Approval (if required)

  • Submit PO for approval based on dollar threshold
  • Manager reviews PO details and budget impact
  • Approves or rejects with comments
  • David notified of approval status

Approval Rules: Dollar thresholds, budget availability, business unit authorization

↓

📧 Send PO to Vendor

  • Generate PO PDF document
  • Email PO to vendor contacts
  • Vendor accesses PO via vendor portal (optional)
  • Set PO status to "Sent to Vendor"
↓

📦 Receive Goods

  • Goods arrive at receiving dock
  • Warehouse staff navigates to PO receiving module
  • Scans or searches for PO number
  • Enters received quantities per line item
  • Notes any discrepancies (quantity or quality issues)
  • Saves receipt record with timestamp

API Call: POST /api/page/purchaseorder/{id}/receive

↓

💰 Invoice Processing

  • Vendor invoice received (email or mail)
  • Accounting matches invoice to PO and receipt
  • Three-way match: PO, Receipt, Invoice
  • Resolve any discrepancies
  • Approve invoice for payment
  • Schedule payment based on terms

👤 Journey 4: Customer Portal Access

Persona: External Customer Contact

Scenario: Customer logs in to view work order progress and documents

🔐 Customer Portal Login

  • Customer navigates to NESI portal URL
  • Enters customer portal credentials
  • OAuth validates customer user type
  • Lands on customer-specific dashboard

Security: Limited access, data filtered by customer organization

↓

📊 View Work Orders

  • Customer sees list of their active work orders
  • Filters by status (Open, In Progress, Complete)
  • Clicks on work order to view details
  • Views project description, timeline, assigned team
  • Reviews work order line items and costs

Read-Only Access: Customers cannot modify work orders

↓

📁 Download Documents

  • Accesses documents tab
  • Views uploaded documents (quotes, invoices, certifications)
  • Downloads PDF documents
  • All downloads logged for audit
↓

📧 Submit Request

  • Customer can submit new service requests
  • Fills out request form with details
  • Uploads attachments if needed
  • Submits request
  • Request routed to appropriate sales/service team
  • Customer receives confirmation email

💡 User Journey Best Practices

🎯 Optimization Tips

  • Minimize Clicks: Common actions should be accessible in 2-3 clicks
  • Smart Defaults: Pre-populate fields based on user context and history
  • Bulk Actions: Allow batch processing for repetitive tasks
  • Keyboard Shortcuts: Power users benefit from keyboard navigation
  • Mobile Optimization: Field users need mobile-friendly interfaces
  • Real-time Feedback: SignalR notifications keep users informed
  • Contextual Help: Inline help and tooltips reduce support needs
