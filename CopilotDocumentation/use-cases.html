📋 NESI Application - Use Cases

Use Case Overview

This document describes the key use cases in the NESI application from the perspective of different actors (users). Each use case details the primary flow, actors involved, preconditions, postconditions, and alternative flows. These use cases represent the core functionality that delivers business value.

🎭 Primary Actors

👨‍💼 Sales Representative 📊 Project Manager 👷 Field Technician 🛒 Purchasing Agent 💼 Manager/Supervisor 💰 Accounting Staff 👤 Customer Portal User 🔧 System Administrator
📝 Use Case 1: Create and Manage Customer Quote
Use Case ID UC-001
Primary Actor Sales Representative
Secondary Actors Manager (for approval), Customer (for acceptance)
Goal Create an accurate quote for customer services/products and track through approval to conversion
Complexity High
Frequency Daily (10-50 quotes per day)

Preconditions

  • Sales Representative is authenticated and has Quote page authorization
  • Customer record exists in system (or can be created)
  • Pricing data is available (labor rates, material costs)
  • Business unit is active and accessible

Main Success Scenario

  1. Sales Rep navigates to Customer record and clicks "Create Quote"
  2. System displays quote creation form with customer data pre-populated
  3. Sales Rep enters quote header information:
    • Quote type (Time & Material, Fixed Price, Cost Plus)
    • Project description and scope
    • Estimated start and completion dates
    • Responsible project manager
    • Terms and conditions
  4. Sales Rep adds line items:
    • Labor: Job type, estimated hours, hourly rate
    • Materials: Part number/description, quantity, unit price
    • Equipment: Asset type, rental period, rate
    • Miscellaneous: Permits, travel, other costs
  5. System automatically calculates:
    • Line item totals (quantity × unit price)
    • Subtotal (sum of all line items)
    • Tax amount (subtotal × tax rate)
    • Grand total
  6. Sales Rep applies discounts or markups if authorized
  7. Sales Rep reviews profit margins and compares to customer rate history
  8. Sales Rep saves quote as Draft
  9. Sales Rep submits quote for internal approval
  10. System routes to Manager based on dollar threshold
  11. Manager reviews and approves quote
  12. Sales Rep generates PDF and emails to customer
  13. Customer reviews and accepts quote
  14. Sales Rep updates status to "Customer Approved"

✅ Postconditions (Success)

  • Quote is saved in database with Approved status
  • PDF quote document generated and archived
  • Customer notified via email
  • Quote ready for conversion to Work Order
  • Quote appears in reports and dashboards

Alternative Flows

3a. Customer Does Not Exist

  1. Sales Rep clicks "Create New Customer"
  2. System displays customer creation form
  3. Sales Rep enters customer details
  4. System validates and saves customer
  5. Resume at step 2 of main flow

4a. Copy Line Items from Previous Quote

  1. Sales Rep clicks "Copy from Template" or "Copy from Quote"
  2. System displays searchable list of templates/quotes
  3. Sales Rep selects source
  4. System copies line items
  5. Sales Rep adjusts quantities/prices as needed
  6. Resume at step 5 of main flow

⚠️ Exception Flows

E1. Manager Rejects Quote
  1. Manager reviews quote and finds pricing issues
  2. Manager clicks "Reject" and enters rejection reason
  3. Sales Rep is notified
  4. Sales Rep reviews comments and revises quote
  5. Resume at step 8 of main flow
E2. Customer Requests Changes
  1. Customer reviews quote and requests modifications
  2. Sales Rep creates revised version
  3. System maintains revision history
  4. Resume at step 3 of main flow
E3. Validation Errors
  • Missing required fields → Error message displayed, cannot save
  • Negative quantities/prices → Error message, must correct
  • Invalid dates (end before start) → Error message

Business Rules

  • BR-001: Quotes over $50,000 require manager approval
  • BR-002: Discount percentages over 15% require approval
  • BR-003: Labor rates must be within defined range for business unit
  • BR-004: Quote must have at least one line item
  • BR-005: Estimated dates must be in the future
  • BR-006: Tax rate is determined by customer location
🔧 Use Case 2: Execute Work Order
Use Case ID UC-002
Primary Actor Project Manager
Secondary Actors Field Technician, Customer, Accounting
Goal Manage work order from creation through completion and invoicing

Main Success Scenario

  1. Work Order is created (from approved quote or directly)
  2. Project Manager assigns team members to work order
  3. Project Manager sets schedule and milestones
  4. System notifies assigned technicians via SignalR
  5. Technicians view work order details and task assignments
  6. Technicians log time against work order as work is performed
  7. Materials are purchased via PO and linked to work order
  8. Project Manager tracks progress and updates status
  9. Technicians upload completion photos/documents
  10. Project Manager marks work order as Complete
  11. Accounting generates invoice based on actual time and materials
  12. Invoice sent to customer
  13. Work Order closed upon payment receipt

✅ Postconditions (Success)

  • Work order completed and closed
  • All labor hours and materials tracked
  • Invoice generated and sent to customer
  • Job cost data available for reporting
  • Customer satisfaction recorded

Alternative Flows

7a. Additional Materials Needed

  1. Technician identifies need for additional materials
  2. Requests materials via work order notes
  3. Purchasing Agent creates PO
  4. Materials received and logged to work order
  5. Resume at step 8

⚠️ Exception: Customer Cancels Work Order

  1. Customer requests cancellation
  2. Project Manager assesses work completed
  3. Partial invoice generated for work done
  4. Work Order marked as Cancelled
⏱️ Use Case 3: Track Employee Time
Use Case ID UC-003
Primary Actor Field Technician / Employee
Secondary Actors Supervisor (for approval), Payroll (for processing)
Goal Accurately record work hours for payroll and job costing

Main Success Scenario

  1. Employee logs into NESI
  2. Navigates to Timesheet module
  3. Selects date for time entry (defaults to today)
  4. Clicks "Add Time Entry"
  5. Selects work order or project from dropdown
  6. Selects pay type (Regular, Overtime, Double Time, PTO)
  7. Enters hours worked (with decimal precision)
  8. Selects job type/activity (Installation, Troubleshooting, Travel, etc.)
  9. Optionally adds notes about work performed
  10. Allocates hours to business unit if multi-unit employee
  11. Clicks "Save" to record entry
  12. System validates entry (hours > 0, not exceeding daily limits)
  13. Entry appears in timesheet grid
  14. Employee reviews weekly timesheet
  15. Employee submits timesheet for approval
  16. Supervisor reviews and approves timesheet
  17. Approved hours exported to payroll system

✅ Postconditions (Success)

  • Time entries saved and approved
  • Hours allocated to work orders for job costing
  • Hours available for payroll processing
  • Timesheet data available in reports

Alternative Flows

6a. Enter Vacation/PTO

  1. Employee selects pay type "Vacation" or "PTO"
  2. System checks available vacation balance
  3. If sufficient balance, allows entry
  4. System deducts from vacation balance

6b. Enter Expense/Per Diem

  1. Employee clicks "Add Expense"
  2. Selects expense type (Mileage, Meals, Hotel, etc.)
  3. Enters amount and uploads receipt
  4. Links to work order for reimbursement

Business Rules

  • BR-010: Daily hours cannot exceed 24
  • BR-011: Overtime automatically applied after 40 hours/week
  • BR-012: Timesheets must be submitted by end of week
  • BR-013: Vacation requests require advance approval
🛒 Use Case 4: Process Purchase Order
Use Case ID UC-004
Primary Actor Purchasing Agent
Secondary Actors Vendor, Warehouse Staff, Accounting
Goal Procure materials/services efficiently while maintaining cost control

Main Success Scenario

  1. Purchasing Agent receives material request
  2. Checks inventory for availability
  3. Searches vendor database by specialty/product
  4. Selects preferred vendor based on price and lead time
  5. Creates new Purchase Order
  6. Links PO to work order for cost tracking
  7. Adds line items (part numbers, quantities, prices)
  8. Allocates costs to business unit(s)
  9. Reviews total and checks budget availability
  10. Submits for approval if over threshold
  11. Manager approves PO
  12. System generates PO document
  13. PO emailed to vendor
  14. Vendor acknowledges and provides ship date
  15. Materials arrive at warehouse
  16. Warehouse staff receives against PO
  17. System updates inventory quantities
  18. Vendor invoice received and matched to PO
  19. 3-way match completed (PO, receipt, invoice)
  20. Invoice approved for payment
  21. Payment processed according to terms

✅ Postconditions (Success)

  • Materials received and in inventory
  • Costs allocated to work order
  • Vendor paid according to terms
  • Purchasing metrics updated

Exception Flows

⚠️ E1. Receiving Discrepancy

  1. Received quantity differs from PO
  2. Warehouse staff notes discrepancy
  3. Purchasing Agent contacted
  4. Vendor contacted to resolve
  5. Partial receipt recorded or return initiated

⚠️ E2. Invoice Mismatch

  1. Invoice amount doesn't match PO
  2. Accounting places on hold
  3. Purchasing Agent investigates
  4. Corrected invoice requested from vendor
📊 Use Case 5: Generate Financial Reports
Use Case ID UC-005
Primary Actor Manager / Accounting Staff
Goal Obtain accurate financial data for decision-making and compliance

Available Reports

Report Name Purpose Frequency
Job Cost Report Analyze profitability per work order Weekly/Monthly
Income Statement Revenue and expenses by period Monthly
Balance Sheet Financial position snapshot Monthly/Quarterly
Customer Rate Analysis Compare pricing across customers As needed
Inventory Usage Track material consumption Monthly
Outstanding Invoices Accounts receivable aging Weekly

Main Success Scenario (Job Cost Report)

  1. Manager navigates to Reports module
  2. Selects "Job Cost Report"
  3. Specifies parameters:
    • Date range
    • Business unit(s)
    • Customer(s) (optional filter)
    • Work order status (Open, Complete, All)
  4. Clicks "Generate Report"
  5. System queries database (stored procedure)
  6. Calculates metrics:
    • Actual labor cost (hours × rates)
    • Actual material cost
    • Total actual cost
    • Revenue (quoted or invoiced amount)
    • Profit (revenue - cost)
    • Profit margin %
  7. Report displayed in grid format
  8. Manager can sort/filter results
  9. Manager exports to Excel or PDF
  10. Report saved for audit trail

✅ Postconditions (Success)

  • Report generated with current data
  • Insights available for decision-making
  • Export available for sharing/archiving
