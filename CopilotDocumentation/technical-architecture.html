🏗️ NESI Technical Architecture

Architecture Overview

NESI is built on a modern N-Tier Architecture that separates concerns across multiple layers, ensuring maintainability, scalability, and testability. The application follows industry best practices with clear separation between presentation, business logic, data access, and database layers.

🎨 Layer Descriptions

1. Frontend / Presentation Layer

Technology Stack: Angular (Modern SPA) + ASP.NET Web Forms (Legacy)

Angular Single Page Application (Primary)

  • Framework: Angular (TypeScript-based)
  • State Management: @ngrx/store for application state
  • Routing: Angular Router for client-side navigation
  • UI Components: Custom components + third-party libraries
  • HTTP Client: Angular HttpClient for API communication
  • Real-time: SignalR client for real-time notifications

ASP.NET Web Forms (Legacy)

  • Purpose: Legacy pages being migrated to Angular
  • Usage: Some administrative and reporting pages
  • Integration: Can embed Angular components in Web Forms

Responsibilities

  • User interface rendering and interaction
  • Client-side validation
  • State management for UI components
  • OAuth token management
  • API consumption via HTTP requests
  • Real-time update handling via SignalR

2. API Layer

Technology Stack: ASP.NET Web API 2 + SignalR + OWIN

ASP.NET Web API 2

  • RESTful Design: HTTP verbs (GET, POST, PUT, DELETE)
  • JSON Serialization: Newtonsoft.Json
  • Authentication: OAuth 2.0 Bearer Tokens via OWIN
  • Authorization: Custom filter attributes (Page/Privilege)
  • Dependency Injection: Ninject for IoC container
  • CORS Support: Cross-origin requests enabled

SignalR Hub

  • Real-time Communication: WebSocket-based push notifications
  • Use Cases: Task assignments, status updates, alerts
  • Hub Structure: Separate SignalR project (NESI.SignalR)

Responsibilities

  • HTTP request/response handling
  • Authentication and authorization enforcement
  • Input validation and model binding
  • Error handling and exception management
  • Response formatting (JSON)
  • Real-time message broadcasting

3. Business Logic Layer (BLL)

Technology Stack: C# Class Libraries

Key Components

  • Business Rules: Complex validation and business logic
  • Workflow Orchestration: Multi-step process coordination
  • Data Transformation: Entity to DTO mapping
  • Calculations: Financial, time, and quantity calculations
  • Integration Logic: External system communication
  • Caching Management: In-memory caching for performance

BLL Projects

Stored Procedures & Views

  • Complex Queries: Performance-critical operations
  • Reporting: Aggregated data for reports

  • Legacy Integration: Existing stored procedure usage

🔧 Key Architectural Patterns

1. Repository Pattern

The Repository Pattern abstracts data access logic, providing a collection-like interface for accessing domain entities. This promotes testability and separation of concerns.

// Example Repository Pattern Usage public class AuthRepository : IDisposable { private NESIEntities _context; public AuthRepository() { _context = new NESIEntities(); } public User FindUser(string username, string password, string ipAddress) { // Data access logic encapsulated in repository var user = _context.Users .FirstOrDefault(u => u.Username == username && u.IsActive); if (user != null && VerifyPassword(password, user.PasswordHash)) { LogLoginAttempt(user, ipAddress, true); return user; } LogLoginAttempt(username, ipAddress, false); return null; } public void Dispose() { _context.Dispose(); } }

Benefits: Testability, maintainability, abstraction of data source

2. Dependency Injection with Ninject

Ninject provides IoC (Inversion of Control) for dependency injection, enabling loose coupling between components and facilitating unit testing.

// Ninject Binding Configuration public class NinjectWebCommon { private static void RegisterServices(IKernel kernel) { kernel.Bind().To(); kernel.Bind().To(); kernel.Bind().To(); kernel.Bind().To(); // ... additional bindings } } // Controller with Dependency Injection public class CustomerController : ApiController { private readonly ICustomerService _customerService; public CustomerController(ICustomerService customerService) { _customerService = customerService; } }

Benefits: Loose coupling, testability, flexible configuration

3. State Management with @ngrx/store

Angular frontend uses @ngrx/store for Redux-style state management, providing a predictable state container with unidirectional data flow.

// State Management Example // Actions export const loadCustomers = createAction('[Customer] Load Customers'); export const loadCustomersSuccess = createAction( '[Customer] Load Customers Success', props<{ customers: Customer[] }>() ); // Reducer export const customerReducer = createReducer( initialState, on(loadCustomersSuccess, (state, { customers }) => ({ ...state, customers: customers, loading: false })) ); // Effects @Effect() loadCustomers$ = this.actions$.pipe( ofType(loadCustomers), switchMap(() => this.customerService.getCustomers() .pipe( map(customers => loadCustomersSuccess({ customers })), catchError(error => of(loadCustomersFailure({ error }))) ) ) );

Benefits: Predictable state, time-travel debugging, improved testability

4. SignalR for Real-Time Communication

SignalR enables bi-directional real-time communication between server and clients using WebSockets (with fallback to other transports).

// Server-Side Hub public class NotificationHub : Hub { public async Task SendTaskAssignment(int userId, Task task) { await Clients.User(userId.ToString()) .SendAsync("ReceiveTaskAssignment", task); } public async Task BroadcastWorkOrderUpdate(int workOrderId, string status) { await Clients.Group($"WorkOrder_{workOrderId}") .SendAsync("WorkOrderStatusChanged", status); } } // Client-Side Connection (Angular) this.hubConnection = new HubConnectionBuilder() .withUrl('/notificationHub', { accessTokenFactory: () => this.authService.getToken() }) .build(); this.hubConnection.on('ReceiveTaskAssignment', (task) => { this.store.dispatch(new AddTask(task)); });

Benefits: Real-time updates, reduced polling, better UX

🔄 Request Flow Example

User Creates a Quote - End-to-End Flow

  1. User Action: User clicks "Create Quote" button in Angular UI
  2. Angular Component: Dispatches @ngrx action: createQuote(quoteData)
  3. @ngrx Effect: Intercepts action, calls QuoteService.createQuote()
  4. Angular Service: Makes HTTP POST to /api/page/quotes with Bearer token
  5. OWIN Middleware: Validates OAuth token, extracts user identity
  6. Authorization Filter: Checks PageAuthorization and PrivilegeAuthorization
  7. API Controller: QuoteController.Post() receives request, validates model
  8. BLL Service: QuoteService.CreateQuote() applies business rules
  9. Repository: QuoteRepository.Add() prepares entity for persistence
  10. Entity Framework: Generates INSERT SQL and executes against database
  11. Database: Saves quote record, triggers fire for audit logging
  12. Response: Success response bubbles back up through layers
  13. @ngrx Store: Updates state with new quote
  14. UI Update: Angular component re-renders with new quote
  15. SignalR: Broadcasts quote creation event to relevant users

⚡ Performance Optimizations

🚀 Caching Strategy

In-memory caching for reference data (business units, tax entities, dropdown lists) reduces database load.

📊 Query Optimization

Eager loading with Include(), stored procedures for complex queries, and indexed columns.

🔄 Async Operations

Async/await pattern throughout API layer prevents thread blocking on I/O operations.

📦 Bundling & Minification

Angular production builds use AOT compilation and tree-shaking for minimal bundle size.
